# Sensors and hardware integration

Development contract0x20261115 rejects older packages and peers. Nominal API/package-envelope/protocol versions remain1; framing and the container header/index are unchanged, while the manifest is FLM3 with per-component logic, budgets and declarations. Rebuild all owned packages; do not erase partitions, grants, settings or private data. grants.bin layout remains unchanged. ambient_light is now persistent and needs explicit consent. Publisher metadata is not signature provenance.

`spec/sensors.json` generates sensor_registry.h: temperature(Celsius),pressure(Pa),humidity(%),ambient_light(lux),acceleration(m/s²),angular_velocity(rad/s). Channel mask bits0..5 use that order. Source0 deterministically selects lowest priority then source_id among sources supporting the entire mask; failure does not silently change primary source.

Core owns the authoritative Broker/cache, Runtime and common authorize path. Backend methods only exchange bounded demand/snapshots; hardware, conversion deadlines and power modes belong to the single OS worker. Backend must outlive Core, notify its owner on completion and honor notBefore/physical min intervals. One measurement serves multiple consumers; slower deliveries coalesce. Foreground and background services have separate owners in the same authoritative Broker; see [background execution](BACKGROUND-SERVICES.md).

Set app_api:1,sensor_api:1 inside the selected project.json components[] entry with Lua capability64. sensor_api adds capability8192; API support is separate from configured hardware and readiness. Sensor operations during loading/validation return invalid_state. In active callbacks use ignite.sensors.catalog(index1..16),read(source,mask,last_known),refresh(source,mask,timeout_ms1..60000),subscribe(source,mask,interval_ms),unsubscribe(handle). First four return(value,error); unsubscribe returns error. catalog returns metadata; end is not_supported. Subscribe/refresh return opaque handles. Up to16 sources,8 subscriptions and 8 pending refreshes per owner, up to40 of each globally across foreground and four services. Foreground tick callbacks share instruction limits and32 native API calls; service callbacks share their model dispatch allowance.

The actual Lua callback is sensor(handle,snapshot,error,drops,refresh_finished), after focused input/touch cancellation and before timers/update. Snapshot includes source_id,generation,sample_id,timestamp_ms,age_ms,status,reason,channels,simulation,last_known,values. Scalar channels expose x; motion exposes x/y/z; each has unit. Timestamp is monotonic conversion completion/register observation, not guaranteed physical acquisition time. Cache reads never refresh timestamps. Status0 absent,1 pending,2 valid,3 stale,4 failed,5 initializing. Saturation/invalid input is failed+invalid_argument. Normal unavailable/stale reads omit values; explicit last_known may include values with unavailable error/status/age. Recovery generations invalidate previous last-known data.

Persistent permissions: sensors.motion,ambient_light,temperature,pressure,humidity (all prefixed sensors.). Installed principal and current grants are checked at creation/read/delivery. Declarations are requests, not grants. Grouped BME280 data is filtered per requested authorized channel. Revoke removes queued notifications and demand; suspend/stop/crash/update/uninstall invalidate app handles. Failed durable revoke returns io_error, denies access in RAM, and must not be presented as saved. Previously delivered values cannot be revoked. Unconfigured source/channel returns not_supported; configured unavailable/pending returns source_unavailable plus state; denied supported operation returns permission_denied. Future/commented TOML is inactive.

ignite.beep(hz,duration_ms) uses audio.play for a narrow real buzzer only; it does not implement audio playback or haptics. OS limits100..10000Hz,5s continuous even with repeated retunes,100ms command spacing,quiet at least previous burst. ignite.brightness(percent,duration_ms) uses current ui.brightness session grant,5..100%,1..5000ms override. Unsupported hardware returns not_supported. Authenticated settings_get/set exposes brightness_mode(manual/automatic),brightness_manual,brightness_fallback(5..100),audio_muted(0/1), and read-only brightness_supported/mute_supported. Automatic brightness requests ALS1Hz,filters new samples with EMA1/4,hysteresis3points,slew5points/s; unavailable ALS uses configurable fallback(default50). Override expires on timeout/consumer change/revoke and restores system policy. These are initial uncalibrated policies.

RTC boot uses validated UTC and monotonic extrapolation. time_set success acknowledges durable Core fallback, then asynchronous RTC write/readback begins. time_status29 returns epoch:u64,state:u8,error:u16:0 Core-only/no RTC,1 pending,2 RTC confirmed,3 Core accepted but RTC failed. Pending timeout5s; another time_set is rejected while pending. RTC failure does not roll back accepted Core time. Configured RTC disables periodic Flash epoch checkpoints; trusted time_set writes fallback once. Sensor deadlines and grant expiry always use monotonic time.

Companion v1 framing/CRC32/little endian is unchanged. Every reply starts with Error:u16. sensor_catalog27(empty request):count:u8; each row source:u16,mask:u8,min/default/max/stale:u32,priority/simulation/temperature_kind/coordinates:u8,status:u8,reason:u16,generation/sample_id/at/age:u64. No values.

sensor_diagnostic28 request action:u8:0 stop;1 start(source:u16,mask:u8,interval_ms:u32,lease_ms:u32);2 read. One explicitly enabled authenticated session lease,maximum30000ms. Interval>=200ms and source minimum,maximum5Hz; faster pulls return quota_exceeded. Start/stop reply empty. Read:source:u16,channels:u8,generation/sample_id/at/age:u64,status:u8,reason:u16,drops:u32,simulation:u8; three IEEE754 f64 LE per set channel bit. Nonfresh reads have channels0 and no doubles. Disconnect,lease expiry and Flare panel closure stop demand; reconnect does not restore a session. Authentication alone never starts telemetry. This is bounded pull/coalescing/backpressure,not raw IMU ODR streaming. Runtime diagnostic logs require an active diagnostic lease; ordinary counters contain no sensor readings.

Simulation uses the same Core/Broker/Runtime and controlled monotonic time with explicitly virtual data,absence,pending,stale,errors,initializing and resets. Remote Preview continues device execution without a second Lua copy. Host tests do not establish physical I2C,latency,power or hardware durability.

Hardware acceptance remains separate: internal RAM/PSRAM,worker watermark,wake/I2C/ADC counts/durations,jitter,missed deadlines,gaps,age/coalescing,touch/render/USB/BLE/install during Flash work,power idle/display/sampling,ALS shutdown failures,RTC oscillator-stop/calendar/readback failures,invalid calibration/saturation/timeouts,power hold/BOOT/reset/recovery. No FPS,hard realtime or battery-life guarantee.

Follow-up backlog:VEML autorange/nonlinearity,verified IMU mounting/calibration/FIFO,wake-on-motion/raise gesture,access-controlled local history with Flash limits,RTC alarms/low-power wake,and a validated charge model. No step counter or medical algorithms are implied.

Motion catalog includes acceleration_range_m_s2,angular_velocity_range_rad_s,mounting_verified. OS QMI8658 uses ±19.6133m/s²,±8.936rad/s and fixed sensor-aligned device axes with identity mounting. Physical enclosure alignment is unverified (mounting_verified=false); UI rotation never changes axes.

Incompatible installed objects and references are retained at startup. A contract change is not storage corruption and must not trigger automatic rollback/object deletion. Explicit launch returns incompatible_contract; incompatible entries are hidden from the executable catalog until rebuilt/reinstalled. Private state and durable grant files are preserved.

[Background services](BACKGROUND-SERVICES.md) use the same Broker/cache with separate instance-bound handles. UI failure/switching does not cancel a live service demand. The package permission union does not replace component declarations.
