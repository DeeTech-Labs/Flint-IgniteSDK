# Самостоятельный Flint IgniteSDK

Репозиторий: [DeeTech-Labs/Flint-IgniteSDK](https://github.com/DeeTech-Labs/Flint-IgniteSDK).

## Сборка и установка

Нужны CMake, компиляторы C/C++20, Python 3; Pillow — для конвертации изображений/шрифтов и интеграционных тестов. Lua 5.4.9 включена с исходной лицензией и проверенным хешем архива; при сборке интерпретатор не скачивается. Команды из корня SDK:

```sh
cmake -S . -B /tmp/ignite-build -DCMAKE_BUILD_TYPE=Debug
cmake --build /tmp/ignite-build --parallel
ctest --test-dir /tmp/ignite-build --output-on-failure
cmake --install /tmp/ignite-build --prefix /tmp/ignite-sdk
/tmp/ignite-sdk/bin/ignite init /tmp/my-clock --id demo.clock --publisher demo
/tmp/ignite-sdk/bin/ignite build /tmp/my-clock/project.json /tmp/my-clock.ignit
/tmp/ignite-sdk/bin/ignite check /tmp/my-clock.ignit
```

На Windows установленный скрипт `ignite` запускается через Python. В исходном дереве передайте `--validator /tmp/ignite-build/ignite-check` в `tools/ignite.py build/check`. Отчёты и диагностика CLI — UTF-8 независимо от кодовой страницы консоли. Ошибочная сборка сохраняет последний успешный пакет. JSON-отчёт показывает объявленные бюджеты и совместимость Runtime, но не измеренную вместимость устройства, подлинность издателя, допуск в магазин или автономность.

## Приложение Lua

`logic: {"language": "lua", "path": "main.lua"}` добавляет одну секцию текстового исходника. Lua-пакет содержит ровно один компонент app/watchface, бит возможностей 64, 48..144 КиБ заявленной внутренней памяти и 1..100000 инструкций Lua на обработчик. Исходник ограничен 16 КиБ, бинарные chunks отклоняются. Текущий контракт разработки — `0x20261105`; пересоберите пакеты этим SDK. Загрузчика старого формата нет.

Исходник возвращает таблицу с `update(dt_ms, pressed)`. Первый вызов при загрузке имеет нулевое время, последующие выполняются Runtime или планировщиком Core. Core ограничивает шаг 100 мс. Ввод требует `input.focused`.

- `ignite.set(node, property, integer)` меняет x/y/w/h поддерживаемых собственных узлов UI. Нумерация с единицы; полноэкранный фон неизменяем. Границы соответствуют кодеку сцены. Ссылки на ресурсы и исполняемые обработчики заменять нельзя.
- `ignite.value(key, integer)` публикует до 16 значений для `${app.key}` в тексте. Ключи: 1..32 строчные ASCII-буквы, цифры и подчёркивания; значения — знаковые i32.

VM использует учитывающий память аллокатор и hook инструкций. Стандартные библиотеки, файловая система, OS, debug, загрузка модулей, корутины, динамическая загрузка и protected-call helpers не предоставляются. Ошибка уничтожает состояние; Core возвращается к часам/восстановлению. Это экспериментальная песочница, а не полный аудит безопасности. Счётчик инструкций не равен реальному времени. Нативные выделения памяти, разбор исходников, C-стек и задержки GC требуют измерений на устройстве.

```sh
/tmp/ignite-sdk/bin/ignite build examples/flappy-bird/project.json /tmp/game.ignit
/tmp/ignite-sdk/bin/ignite run /tmp/game.ignit --frames 120 --press-every 24 --image /tmp/game.ppm
```

`run` — детерминированная симуляция без окна с искусственными нажатиями и итоговым PPM, а не интерактивная игра. Симулятор Flare использует тот же Core для обновлений по времени. Физический игровой ввод на этом этапе не подключён.

Сборки компьютера включают Lua по умолчанию; `-DFLINT_ENABLE_LUA=OFF` проверяет отклонение Lua-пакетов. Spark включает те же исходники/лимиты через `CONFIG_FLINT_LUA_RUNTIME`. Вложенные вызовы C ограничены 40; основной стек прошивки — 32 КиБ. Заголовки моста C++ включают `<climits>` для сохранения целочисленного ABI C/C++ ESP-IDF.

На Spark физически проверены анимация, повторное переключение приложений, ограничения исполнения/памяти и восстановление заводских часов. Сырые отчёты устройства хранятся вне репозитория; в PR указываются краткие результаты. Изменения движка, лимитов или нативных привязок требуют повторной проверки на устройстве.

Аутентифицированный метод Companion 21 (`diagnostics`) возвращает строки с целыми значениями: текущая/пиковая память VM, последняя ошибка логики и аппаратные поля памяти, стека, времени. Максимальные задержки накапливаются с загрузки и включают переходы/восстановление; это не устойчивый FPS и не чистое время интерпретатора. `tools/companion.py` — отдельный USB-клиент разработчика с pyserial, недоступный приложениям.

## Единый источник и закреплённые потребители

OS и Flare подключают SDK как `platform/` на неизменяемом коммите. Копирования, экспорта и синхронизации исходников нет.

```sh
git clone --recurse-submodules <consumer-repository>
git submodule update --init --recursive
```

Общие изменения вносятся, проверяются и публикуются в SDK, затем ссылка подмодуля обновляется в каждом потребителе и проверяется вместе с адаптерами. Не следуйте автоматически движущейся ветке. Одинаковые исходники устраняют расхождение реализаций, но не отменяют проверки контракта, сборки и возможностей.

Потребители на компьютере используют `add_subdirectory(platform)` и `Flint::Platform` либо установленный SDK с `find_package(FlintPlatform 1.0 EXACT CONFIG REQUIRED)`. ESP-IDF компилирует те же исходники через адаптер компонента, а не библиотеку компьютера. Конфигурация платы, транспорт и дисплей остаются в OS; Qt UI — во Flare. Заводские пакеты и примеры относятся к этой общей версии контракта.

## Дальнейшая работа

Для других плат и нативных привязок повторно измеряйте ресурсы, задержки и восстановление. Квоты инструкций не задают временную границу C-кода, парсера, GC и файлового восстановления. Постоянное хранение и API устройства с проверкой разрешений, интерактивный ввод, стили и редактор Studio — отдельные задачи. Подписи и публикация в маркетплейсе также остаются отдельной работой.

[Лицензии и дополнительные разрешения](LICENSING.md): разработка платных независимых Ignite разрешена; коммерческое встраивание Runtime — отдельный сценарий.
