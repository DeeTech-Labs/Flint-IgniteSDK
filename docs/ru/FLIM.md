# FLIM v2 и иконки Ignite

[English](../en/FLIM.md)

Контракт `0x20261113`: принимаются только FLIM v2 и manifest FLM2. Старых декодеров нет; все пакеты, factory и примеры пересобираются. Устройство читает подготовленный FLIM, не PNG/SVG. Несжатое хранение обеспечивает прямой доступ к строкам; масштабирование выполняется на компьютере.

## Формат

Числа little-endian, строки сверху вниз, пиксели слева направо. Нативные структуры C++ не сериализуются. Заголовок ровно 16 байт:

| Смещение | Поле | Ограничение |
| --- | --- | --- |
| 0 | magic, 4 байта | `FLIM` |
| 4 | version, u8 | 2 |
| 5 | representation, u8 | 1=A4, 2=INDEX8, 3=RGB565+A8 |
| 6 | width, u16 | 1…320 |
| 8 | height, u16 | 1…320 |
| 10 | paletteCount, u16 | INDEX8: 1…256; иначе 0 |
| 12 | reserved, u32 | 0 |

Сразу за заголовком идут `paletteCount` записей по 3 байта: RGB565 u16, затем A8 u8. RGB565: красный в битах 15…11, зелёный 10…5, синий 4…0. Затем без выравнивания располагаются строки:

| Представление | Байтов на строку | Данные |
| --- | --- | --- |
| A4 | `(width+1)/2` с целочисленным делением | старший nibble — чётный x, младший — нечётный; неиспользуемый младший nibble последнего байта каждой нечётной строки равен 0 |
| INDEX8 | width | u8 индексы, каждый строго меньше paletteCount |
| RGB565+A8 | width×3 | последовательные тройки RGB565 u16 + A8 u8; отдельной alpha-плоскости нет |

Полная длина строго `16 + 3×paletteCount + stride×height`, без хвостов. Размеры проверяются до вычисления смещений; при пределах 320 произведения укладываются в u32. Отсутствующие данные, неизвестные тип/версия, неверные индексы/резерв/padding отклоняются. Размер ресурса ограничен также пакетом 1 MiB.

Alpha непредумноженная: A4 преобразуется как `n×17`. Ноль пропускает пиксель, 255 записывает цвет напрямую. Для остальных значений каждый канал RGB565 смешивается с фактическим canvas: `(src×a + dst×(255-a) + 127)/255`, целочисленно. Это смешивание в кодовых значениях RGB565, без линейного цветового пространства. Для A4 src задаёт `Op.color`, для цветных изображений он хранится в ресурсе. Byte-swapped canvas обрабатывается через существующие `get/pixel`.

## Проект и manifest

Иконка приложения имеет фиксированные 48×48 пикселей: две колонки по124px на canvas280×240, ячейка94px с шагом100px, подпись под иконкой. Устройство не масштабирует иконки. Поле проекта:

```json
"icons": {"main": 100, "mask": 101, "light": 102, "dark": 103},
"resources": [
  {"id": 100, "path": "icon.png", "format": "image", "representation": "INDEX8", "size": [48, 48]},
  {"id": 101, "path": "mask.png", "format": "image", "representation": "A4", "mask": "alpha", "size": [48, 48]}
]
```

`main` обязателен, если присутствует любой вариант. `main/light/dark` — INDEX8 или RGB565+A8, `mask` — A4. Поле `icons` можно полностью опустить. В FLM2 после последнего component всегда следуют четыре u32 ID в порядке main, mask, light, dark; 0 означает отсутствие. Ссылки должны указывать на resource-секции. Формат остальных полей manifest сохраняется. Компилятор проверяет подготовленные иконки; native manifest проверяет ссылки, а содержимое изображения безопасно проверяется при использовании. Повреждённая иконка не делает приложение неисполняемым. Ошибка SHA-256 всего пакета по-прежнему блокирует установку.

Тема задаёт `appearance=light|dark` (по умолчанию light), `icons=normal|themed` (по умолчанию normal), RGB565 `accent`, `surface`, `pressed`, `muted`, `background`, `text`. В normal выбирается light/dark при наличии, иначе main. В themed — mask при наличии, иначе main, без выбора light/dark. Недоступный, повреждённый или неверного размера/представления выбранный ресурс заменяется системной плиткой. A4 окрашивается `theme.accent`. Инверсии цветных изображений нет.

Сцена получила `CatalogIcon=7` (`kind: "catalog_icon"`), размер48×48, extra — индекс каталога+1, 0 — стандартная иконка. Требуются `packages.list` без scope и `CapInteractiveUi`. `ignite.set(ui.icon, 'catalog', index)` задаёт индекс0…65534. `ignite.catalog(index)` возвращает `name, target, error`; прежнего symbol нет. Названия ограничиваются шириной и UTF-8 границами, дополнительно учитывается лимит ответа192 байта. Имена manifest должны быть корректным UTF-8 без ASCII control characters. `Scene.resourceRevision` — только derived поле в RAM: смена каталога вызывает dirty redraw, на провод оно не сериализуется.

## Конвертер

```sh
python tools/flim.py icon.png icon.flim --representation INDEX8 --size 48 48 --colors 256 --preview quantized.png
python tools/flim.py mask.png mask.flim --representation A4 --mask alpha --size 48 48
python tools/compile_ignite.py examples/icons/project.json icons.ignit
```

Растры читает Pillow. `size` явно задаёт выходные размеры; Lanczos с обработкой alpha используется только на host. SVG поддерживается через необязательные host CairoSVG и системный Cairo (`pip install CairoSVG`, лицензии LGPL-3.0/Cairo LGPL-2.1 или MPL-1.1); встроены только инструкции вызова, не библиотеки. SVG требует `size`, допускает самодостаточные векторные фигуры, без scripts, image/foreignObject/style, DTD, внешних href/url/base/import. В устройстве новых зависимостей нет. Если backend недоступен, ошибка явная; можно экспортировать PNG.

Представление по умолчанию RGB565+A8: автоматического палитрового квантования нет. INDEX8 выбирается автором. Если уникальных пар RGB565/A8 достаточно для палитры, они сохраняются точно; иначе Pillow FASTOCTREE квантирует RGBA без dithering до `colors` (1…256). Разные alpha одного цвета расходуют отдельные записи. Прозрачный RGB нормализуется к0. Конвертер сообщает размеры, представление, размер файла и composite RMSE на чёрном и белом фоне; это диагностическая метрика, не гарантия качества. `preview` содержит действительно квантованный RGBA PNG. При заметных артефактах используйте RGB565+A8. Для A4 нужен явный `mask=alpha` либо `luminance` (яркость×alpha); полноцветный рисунок автоматически в маску не превращается. Встроенный пример воспроизводится `python examples/icons/generate_assets.py`.

## Память и Flash I/O

Декодер использует строку максимум960 байт и палитру768 байт внутри уже существующего scratch глифов4096 байт `ResourceManager`. Обработчики текста и изображений последовательны; alpha глифа потребляется до следующей операции. Дополнительного framebuffer или массива RGBA нет. `FlimDecoder` хранит только source, размеры и spans; ResourceManager запрещает копирование из-за этих views.

Кэш — шесть фиксированных записей File/Package/View, без пикселей. FILE открывается без stdio-буферизации; allocator/FILE и LittleFS всё ещё имеют собственные расходы. Текущий OS LittleFS cache_size=512, поэтому для шести файлов нужно учесть до3072 байт только файловых кэшей, плюс объекты VFS/FILE. Это оценка, не измерение heap на плате. Кэш закрывается перед изменениями пакетов через Core, сбрасывается по revision, runtime generation и режиму темы; изменение accent отражается без цветового кэша. При прямом использовании PackageManager вызывающий код должен закрывать открытые файлы до мутаций LittleFS.

Холодный miss сканирует существующий каталог через PackageManager, включая существующие проверки пакетов, и потоково проверяет SHA-256 открываемого пакета; файл целиком в RAM не загружается. Это существенно дороже чтения одной иконки. Затем один раз проверяются все строки и индексы выбранного ресурса, включая невидимые. На тёплом redraw читаются заголовок, палитра и только пересечение строк с clip; SHA-256 повторно не считается. Для полной48×48:49 вызовов чтения A4/RGB565+A8, 50 INDEX8; маленький clip читает только нужные пиксели с округлением до байта A4. Palette читается целиком при draw, но только одного текущего изображения. Если пакет велик, следует оценивать холодный miss и каталог отдельно от decoder benchmark.

Размеры с заголовком: A4=1168; INDEX8=`2320+3N`, максимум3088; RGB565+A8=6928 байт. Дополнительного A8 у каждого пикселя INDEX8 нет. Непрозрачные пиксели обходят blending, прозрачные — чтение/запись canvas, но их индексы или alpha всё равно читаются из Flash.

## Проверки и измерения

`flim_decoder` проверяет три представления, alpha0/255/промежуточные, odd-width/padding, палитры1/2/6/16/255/256, плохие индексы, обрезания, неверные размеры/версию/тип, clipping и swapped canvas. `app_icons` проверяет конвертер, manifest, выбор/отсутствие вариантов, системный fallback, install/update/remove и package integrity. Существующие touch/system_ui проверки покрывают launcher, длинные UTF-8 названия, прокрутку и системные состояния. launcher_icons проверяет120 приложений и длинные ID; размеры image/catalog узлов нельзя произвольно менять из Lua. У renderer без Core, в том числе remote Preview с одним foreground-пакетом, CatalogIcon использует стандартную иконку; индекс каталога не интерпретируется как ID ресурса активного пакета.

Воспроизводимый host benchmark:

```sh
python tools/benchmark_icons.py build/flim_tests.exe build/icon-bench
```

Он создаёт monitor, сглаженное кольцо и RGBA gradient, каждый в трёх представлениях. `validate_us` включает open/header/palette и все строки; `draw_us` включает open/header/palette и полный draw48×48, по200 итераций. Это время файловых чтений host с тёплым OS-cache, без поиска приложения, проверки всего пакета и SPI. Результаты конкретного прогона фиксируются в отчёте задачи. `sizeof` объектов даёт размер C++-состояния, не полный peak heap. Время, пик heap, Flash/RAM сборки и качество на физическом ESP32-S3 проверяются отдельно; host benchmark их не устанавливает.

[Результаты host и расчёт RAM](FLIM-BENCHMARK.md)

Derived resourceRevision включает поколение кэша: каталог, режим темы и ошибки чтения. Core синхронизирует его до dirty comparison; при отказе тёплого ресурса после clipped redraw запрашивает следующий полный кадр.

После операции ResourceManager/Runtime закрывают borrowed Source декодера до уничтожения локального View/read-context. Scratch остаётся общим; последующее validate без нового open возвращает invalid_state.
