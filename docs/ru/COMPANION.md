# Companion Demand v1

Расширение согласуется через capability `256` в обычном `hello`. FLCP v1,
существующие method ID и `ContractRevision` сохраняются: формат пакетов не меняется.
Клиенты без capability не должны подписываться. Неизвестные capability игнорируются,
если они не входят в требуемый клиентом набор.

Все числа little-endian. Запросы и ответы имеют ненулевой request ID; события:
`reply=0`, `id=0`, method `companion_state` (25), без поля ошибки. Ответы по-прежнему
начинаются с `u16 Error`. Событие не завершает ожидающий запрос и не меняет его timeout.
Транспорт сериализует целые кадры; события допускаются между ответами.

| ID | Метод | Payload запроса |
|---|---|---|
| 22 | companion_subscribe | u16 version=1, u8 enabled (0/1) |
| 23 | companion_bind | u16 version=1, u8 kind=1, u64 demandGeneration |
| 24 | companion_sample | u16 version=1, u8 kind=1, u64 demandGeneration, u32 cpu, u32 ram |
| 25 | companion_state | только событие |

`kind=1` означает CPU/RAM. Образцы выражены в сотых долях процента (0..10000).
Событие: `u16 version=1, u8 kind=1, u64 demandGeneration, u8 state,
u64 consumerGeneration, u32 sampleIntervalMs=2000, u32 ttlMs=10000`.
Состояния: 0 — нет активного потребителя, 1 — нет разрешения, 2 — данные нужны.
Подписка даёт начальный снимок. Максимум четыре подписчика; повторная подписка
не занимает новый слот. Повторные изменения объединяются в последний снимок,
отдельной очереди событий нет. На подписчика — не чаще одного события за 100 мс,
начальный снимок отправляется сразу. Снимок не превышает 64 байт.

Подписка и binding требуют authenticated compatible Session с ненулевым ID.
Поставщик привязан к сессии, виду данных и demandGeneration. Изменение приложения,
suspend/resume, каталога или действующего разрешения меняет demandGeneration и
инвалидирует binding и старые образцы. Другой клиент не может перехватить живой
binding; после disconnect поставщика либо смены потребности можно привязать новый.
Приём ограничен одним образцом за 1000 мс; срок актуальности — 10 секунд.
Permissions проверяет SDK при binding, приёме и выдаче значений приложению.

Прежний `metrics` (16) сохраняется для старых клиентов, с привязкой к сессии и
поколению потребителя; он не защищает от задержанного образца на стороне старого
клиента, поэтому новые поставщики используют только методы 22–25. Существующий
binding нельзя заменить legacy-запросом другой сессии.

Core остаётся единственным владельцем состояния. Адаптер вызывает `takeCompanionEvent`
только при свободном месте TX и отправляет результат целым кадром. SDK не знает
FreeRTOS, USB и BLE. Без поставщика локальное приложение продолжает работать.


## Закрытие логической сессии

Capability `512` объявляет метод `session_close` (26), запрос без payload и обычный
ответ `Error`. Он требует authenticated compatible Session. ACK подтверждает
инвалидацию только этой сессии: её подписок, binding, внешних данных и ещё не
завершённой проверки установки. Уже опубликованный пакет не откатывается.

Flare при явном отключении отправляет close через USB и ждёт ACK до 100 мс без
блокировки GUI, после чего закрывает порт. При ошибке/timeout результат установки
может быть неопределённым для клиента; после reconnect нужно проверить каталог.
BLE disconnect обрабатывается аппаратным событием. Новый USB/BLE hello создаёт
новую логическую сессию даже при неизменившемся физическом соединении.

Binding поставщика имеет lease 10 секунд с последнего принятого образца (или
первоначального bind до первого образца). Истечение освобождает binding, меняет
поколение и уведомляет оставшихся подписчиков; задержанный образец старого
поколения отклоняется. Неактивный поставщик не удерживает источник бессрочно.

## Политика BLE (контракт)

Capability `CapBlePolicy` (1024) разрешает `settings_get/settings_set` ключа `ble_enabled`: строка `1` включает доступность BLE, `0` выключает. Отсутствующее значение означает `1`, чтобы миграция не отключала беспроводной доступ. Это отдельная persistent политика, не согласие Companion. SDK проверяет значение и аппаратную допустимость, атомарно сохраняет настройки, затем передаёт намерение адаптеру; actual state и ошибки старта доступны в diagnostics адаптера. Принятие настройки не означает завершения аппаратного перехода. При выключении все BLE-сессии и очереди инвалидируются; bond keys сохраняются. Текущий профиль не имеет кнопок/touch: включение после `0` возможно через USB. FLCP и package ContractRevision не меняются.
