# Текст и вёрстка

[Оглавление](README.md) · [English](../en/UI-LAYOUT.md)

За расположение элементов отвечает автор приложения: оставляйте поля экрана, место для
переводов и длинных значений, задавайте непересекающиеся области соседних элементов.
Renderer не исправляет вёрстку автоматически, не уменьшает шрифт и не включает бегущую строку.

Обычный `kind: "text"` сохраняет свободное позиционирование: `y` — baseline, а `center`
центрирует строку относительно `x`. Эта модель остаётся доступной без адаптивной обработки.

Если нужен ограниченный текстовый блок, явно задайте `overflow`, `w` и `h`:

```json
{"kind":"text","x":12,"y":128,"w":256,"h":84,
 "text":"Status: ${app.status}","overflow":"wrap"}
```

Этот фрагмент размещается в `components[].ui` после фонового rect 280×240. Именно такой
блок используется в [примере UI + service](../../examples/thermometer-service/project.json).
Убедитесь, что следующее поле начинается ниже `y + h`, а `x + w` помещается на экране.

В режиме блока `x,y` — **верхний левый угол**, размеры `w,h` — целые 1..640 пикселей.
`center: true` центрирует каждую строку внутри блока. Размер шрифта остаётся выбранным автором.

| `overflow` | Поведение |
| --- | --- |
| `clip` | Одна строка, пиксели за пределами блока отсечены. |
| `ellipsis` | Одна строка; если текст не помещается, целые UTF-8 codepoints заменяются в конце на `…`. |
| `wrap` | Перенос по пробелам/явным `\n`, длинное слово делится между codepoints. Строки не пересекаются. Последняя видимая строка получает `…`, если остался текст. |

Высота строки определяется метриками шрифта. Если в `h` не помещается даже одна полная
строка, текст не рисуется: компилятор не выбирает другой шрифт и не увеличивает блок.
Всегда проверяйте размер с нужным шрифтом и переводами. Физический экран дополнительно
отсекает пиксели вне canvas; это не означает, что вёрстка корректна.

Блок не добавляет scene operations, динамических буферов или периодических wakeups.
Лимиты текста/scene остаются прежними. Произвольные данные приложения не переносятся
в соседние элементы; обрезанный текст сам по себе не становится доступным через UI.
Для полного описания предусмотрите отдельный экран, явное раскрытие или прокрутку,
реализованные автором приложения.

ContractRevision `0x20261115` расширяет flags текстовой операции без изменения размера
scene op, nominal package/API/Companion versions. Старые несовместимые пакеты/peers
отклоняются. Пересоберите пакеты, factory и оба потребителя; private storage и grants
не требуется стирать. Тест: `ctest --test-dir build/docs-sdk -C Debug -R text_layout --output-on-failure`.

Полный проверочный [пример text-layout](../../examples/text-layout/project.json) показывает
перенос, многоточие, длинное слово и обычную baseline-строку. Его отступы проверены
на текущей Spark с физически скруглённым LCD; для другой панели проверьте геометрию заново.
